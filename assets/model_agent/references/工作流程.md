## 分析流程

### 第零步：附录检查（必须最先执行）

检查工作目录中是否存在以下文件夹：
- `附录/`、`appendix/`、`Appendix/`
- `附件/`、`data/`、`Data/`

**如果存在**：使用 xlsx skill 读取Excel数据文件。

**如果不存在**：直接进入题目理解。

### 第一步：题目理解

| 信息类型 | 说明 |
|---------|------|
| 问题背景 | 题目的实际背景和应用场景 |
| 问题类型 | 优化、预测、评价、分类等 |
| 数据情况 | 已知数据、待求数据、数据特点 |
| 约束条件 | 各种限制条件和边界条件 |
| 目标要求 | 需要解决的具体问题 |

### 第二步：模型选择

**在确定数学模型时，必须将对应的论文标题、作者、年份、来源等信息同步记录到分析文档中。**

**防冗余原则（必须遵守）**：
- 每个模型必须承载独特且不可替代的分析维度
- 模型之间应形成互补证据链，而非重复验证同一结论
- 如果两个模型的输出揭示的是同一层面的信息，应删除或替换其中之一

#### 模型类型参考

| 问题类型 | 推荐模型 |
|---------|---------|
| 优化问题 | 线性/整数/非线性规划、多目标规划、动态规划、图论模型 |
| 预测问题 | 时间序列分析、回归分析、灰色预测、神经网络（谨慎使用） |
| 评价问题 | AHP、熵权法、TOPSIS、模糊综合评价 |
| 分类问题 | 聚类分析、判别分析、支持向量机 |

### 第三步：算法设计

1. **求解思路**: 详细的求解步骤和方法
2. **算法流程**: 清晰的算法流程图或步骤描述
3. **评价指标**: 模型好坏的评判标准
4. **参数设置**: 关键参数的选择和调整方法

### 第四步：可视化设计

**可视化规划**: 按以下三类系统规划需要绘制的图表，确保每类至少 1-2 张图：

**① 原始数据可视化**（EDA 阶段，数据拿来先画图）

- 数据分布：直方图、箱线图、密度图 → 了解数据范围和异常值
- 相关性分析：热力图、散点图矩阵 → 发现变量间关系
- 时序趋势：折线图 → 观察数据随时间的变化模式
- 组成结构：饼图、堆叠柱状图 → 了解数据构成

**② 中间产物可视化**（模型运行阶段，展示求解过程）

- 收敛曲线：迭代次数 vs 目标函数值 → 展示优化过程
- 模型对比：分组柱状图 → 不同模型在同一指标下的性能对比
- 参数分析：灵敏度折线图 → 参数变化对结果的影响
- 误差分析：残差图、QQ 图 → 验证模型假设
- 混淆矩阵：热力图 → 分类模型评估

**③ 最终结果可视化**（核心结论，论文直接使用）

- 最终方案对比：柱状图→ 展示不同方案的最终指标
- 预测结果展示：折线图+置信区间 → 实际值与预测值对比
- 综合排名/评价：雷达图、气泡图 → 多维度综合展示
- 地理分布：地图热力图 → 空间数据分析
- 结果汇总表+趋势：组合图 → 最终结论的核心视觉支撑

**规划原则**：每类至少 1 张图，每题至少 3-5 张图。先列清单（如："问题1：箱线图(原始数据) + 收敛曲线(中间) + 柱状图对比(最终)"），再开始编码。

### 第五步：术语规范

建立术语表格，确保全文术语一致性：

1. 收集题目和分析过程中的所有专业术语
2. 统一定义，给出明确的中文定义
3. 提供标准的英文翻译
4. 统一数学符号的使用
5. 产出 `术语表格.md`

## 缺失输入处理规则

在建模分析过程中，常遇到输入信息不足的情况。按以下规则处理：

### 规则一：数据不足

| 场景 | 处理方式 |
|------|---------|
| 题目没有给具体数据 | 使用符号参数建模，标注"需实际数据代入" |
| 数据含有大量缺失值 | 先尝试插补，插补率>30%时在论文中说明局限性 |
| 数据规模太小（<10条） | 优先选择灰色预测、参数检验等小样本方法 |
| 数据只有宏观总量 | 检查能否做比例分配或假设分布，在假设中说明 |

### 规则二：模型不适用

| 场景 | 处理方式 |
|------|---------|
| 首选的模型假设不成立 | 记录为什么，选择备选方案，在论文中说明 |
| 所有标准模型都不完全匹配 | 组合2-3个模型分阶段求解，或适当简化问题 |
| 题目是交叉领域 | 拆分为多个子问题，每个子问题用最匹配的模型 |
| 计算资源超出合理范围 | 降低精度要求或简化模型，在论文中说明取舍 |

### 规则三：问题类型不明确

按照以下决策树判断：

```
题目描述更偏"找到最佳方案"？                    → 优化类
题目描述更偏"推测未来趋势"？                    → 预测类
题目描述更偏"比较多个选项"？                    → 评价类
题目描述更偏"发现数据中的模式"？                → 分类/聚类
同时涉及以上多种？                              → 组合类，拆分子问题
```

### 规则四：不确定性处理

- **数据有噪声**：在建模时引入鲁棒性考量，加灵敏度分析
- **参数不确定**：做区间估计而非点估计，给出置信范围
- **模型不确定**：用多个模型交叉验证，在论文中对比
- **假设有争议**：在论文中显式列出每个假设，并说明违反假设的后果

### 规则五：何时询问用户

**必须询问用户的情况**：
- 编程语言未指定
- 题目有多个理解方向且无法判断哪个更符合出题意图
- 需要做比"合理假设"更强的约束性假设

**不需要询问、直接做合理假设的情况**：
- 缺失的输入数据可以通过已有数据推导
- 通用的参数默认值（如交叉概率0.8、显著性水平0.05）
- 标准的建模流程选择（如先预处理再建模）

> **核心原则**：能做合理假设的不要问用户，但所有假设必须记录在分析文档中。
> nature-writing 的规则同样适用：如果核心信息缺失，先写占位符 (placeholder) 并标注，
> 不要编造数据。

## 模型选择原则

| 原则 | 说明 |
|------|------|
| **高效性** | 优先选择计算速度快、效率高的模型 |
| **准确性** | 确保模型能够准确描述和解决问题 |
| **简洁性** | 在满足要求的前提下，选择相对简单的模型 |
| **创新性** | 避免选择过于常见、使用人数过多的简单模型 |
| **实用性** | 尽量避免使用需要长时间训练的复杂模型 |

**谨慎使用的模型**：神经网络（仅在传统方法效果不佳时）、机器学习模型（优先尝试传统模型）、深度学习模型（仅在处理复杂高维数据时）

必须产出独立的题目分析文档 `建模方案.md`，包含以下章节且每个章节预留所需图片的字段：

```markdown

## 二、模型选择
### 2.1 模型选择依据
### 2.2 所选模型介绍
### 2.3 参考文献信息（必须记录论文信息）

## 三、算法设计
### 3.1 求解思路
### 3.2 算法流程
### 3.3 关键技术
### 3.4 评价指标

## 四、数据要求
```

同时依据以上内容丰富产出每一问的题目分析文档 `qN方案.md`，和公式推导`qN模型公式.md`。
